# AgentLab 初步运行计划

**目标：** 为本科生提供一个容易开始、能够持续迭代的 AI Agent 科研与创新入口。AgentLab 同时承担公开介绍、入门引导、项目匹配和学生共建四项工作。

## 一、运行原则

1. **先让学生开始，再逐步加深。** 不把论文、数学基础或已有科研经历作为所有项目的统一门槛。
2. **年级建议学习节奏，能力和兴趣决定任务起点。** 同一项目可以拆成不同难度的工程、实验和研究任务。
3. **先完成小挑战，再匹配正式项目。** 用 7–14 天的任务了解学生的投入、动手能力和复盘习惯。
4. **成果不局限于论文。** 工程 Demo、开源工具、复现报告、竞赛作品和创新项目都可以是阶段成果。
5. **公开方向，内部讨论未公开 Idea。** 网站只介绍主题、学习入口和已获准公开的成果；具体研究问题按项目授权访问。
6. **共用工具要有持续贡献。** 每个正式项目在结束时留下一项可复用资产，例如代码、模板、教程或复盘。

## 二、公开入口和内部空间

| 空间 | 用途 | 可以放什么 |
|---|---|---|
| AgentLab 公开网站 | 介绍计划、方向、入门路线和申请方式 | 公开学习资料、入门挑战、获准公开的作品 |
| 内部项目空间 | 管理学生、任务、实验和进度 | Idea、项目卡、代码、数据、会议记录，按项目授权 |

初版网站提供了路线建议器；选择只在浏览器本地处理，不发送或保存。初期申请通过学校邮箱联系导师。后续如需统一表单，应使用学校认可且权限受控的工具，不把个人信息收集到公开 GitHub Issue。

## 三、学生加入路径

**了解方向 → 选择入门挑战 → 交流匹配 → 进入项目 → 按里程碑迭代 → 复盘并留下公共贡献**

入门挑战提供三类选择：

- **Build：** 实现一个能调用简单工具的 Agent，提交代码和 README。
- **Research：** 复现公开资料中的一个小实验，提交记录、结果和一个问题。
- **Creative：** 围绕真实场景完成一个最小 Demo，说明目标用户和下一步改进。

任务应提供可运行模板、完成标准和提交方式。尽量不要求付费 API、GPU 或复杂环境。

## 四、培养和项目管理

### 成长层次

| 阶段 | 核心目标 | 示例成果 |
|---|---|---|
| L0 Explorer | 认识 Agent、掌握基本工具 | 入门挑战、短报告 |
| L1 Builder | 独立完成小型 Agent 项目 | 可运行 Demo、代码仓库 |
| L2 Researcher | 复现基线并提出可检验问题 | 实验记录、研究原型 |
| L3 Contributor | 主导任务并帮助新成员 | 论文、工具、竞赛成果或项目复盘 |

这不是按年级晋级的制度。学生可根据已有基础从合适阶段进入，也可以在不同项目间切换。

### 统一项目阶段

1. **S0 定义：** 写清问题、目标、负责人和最小交付物。
2. **S1 基线：** 建立环境并运行公开基线，保存配置与结果。
3. **S2 探索：** 针对一个观察提出假设，开展小规模验证。
4. **S3 验证：** 完成公平对比、必要的消融和失败分析。
5. **S4 交付：** 形成论文、工具、作品或竞赛材料。
6. **S5 复盘：** 总结结论、局限和下一位同学可复用的内容。

每个项目维护一张项目卡，至少记录方向、难度、项目负责人、当前阶段、下一个里程碑、交付物和可见范围。项目具体研究内容按需保密。

## 五、角色分工

- **导师：** 确认研究方向和项目边界，审批公开内容，处理需要学术判断的立项与调整。
- **学生负责人：** 协助维护网站与公共资料，整理申请和新人挑战进度，提醒项目负责人更新里程碑，汇总需要导师决策的问题。
- **项目负责人：** 拆分任务、维护项目卡、组织短周期检查，按阶段提交记录和成果。
- **项目成员：** 完成分配任务，记录实验和决策，在项目结束时补充一项可复用资产。

建议学生负责人每周投入约 2–4 小时；每周更新一次项目状态，每月和导师进行一次 20–30 分钟维护复盘。角色先试运行 6 周，再根据实际负担调整。

## 六、首月计划

| 时间 | 工作 | 可检查结果 |
|---|---|---|
| 第 1 周 | 发布网站初版；确定学生负责人和备份联系人；整理申请回应模板 | 网站可访问；维护职责清单；邮件申请模板 |
| 第 2 周 | 试跑 1–2 个 Starter Challenge；邀请少量同学试用路线建议器 | 任务说明、试用反馈、首轮 FAQ |
| 第 3 周 | 根据反馈修订挑战；建立内部项目卡和周状态模板 | 统一模板；首批学生匹配记录 |
| 第 4 周 | 开展一次成果分享；收集可公开的 Demo 和贡献 | 经确认的成果条目；改进清单 |

首月不追求项目数量，重点是验证“学生能否看懂入口、能否独立完成第一步、导师是否能用较少沟通完成匹配”。

## 七、资料入口

- [Hugging Face 智能体入门课程（中文）](https://huggingface.co/learn/agents-course/zh-CN/unit1/introduction)：从 Agent、工具和思考—行动—观察循环入门，并构建第一个 Agent。
- [Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)：理解工作流与 Agent 的区别，并从简单、可组合的设计开始。
- [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)：把安全方向落实到 Agent 行为、工具使用、权限和运行环境。
- [Model Context Protocol 2026-07-28 规范](https://modelcontextprotocol.io/specification/2026-07-28)：按需了解 Agent 应用与外部工具、数据源的连接方式；建议完成第一个 Demo 后再读。

## 八、首轮检查指标

首月只观察少量指标：

- 有多少学生能在一分钟内说清楚 AgentLab 可以做什么、如何开始；
- 入门挑战的完成率和主要卡点；
- 学生是否能在项目匹配后持续提交可检查的进展；
- 每个完成项目是否留下复用资产；
- 学生负责人和导师的维护时间是否可持续。

根据这些结果调整流程，不以注册人数或“必须发论文”作为唯一成效标准。
