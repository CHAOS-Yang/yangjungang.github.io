# AgentLab 网站共建指南

AgentLab 网站位于个人主页仓库的 `agentlab/` 目录。共建的目标是让新同学更容易开始学习和实践，而不是把所有组内材料公开。

## 学生负责人

学生负责人协调网站日常更新，建议每周留出约 2–4 小时：

- 每周查看待处理的 Pull Request 和网站反馈，整理下一步维护清单；
- 维护公开学习路线、入门链接和 FAQ，定期检查链接是否可用；
- 把较大的修改拆成小任务，邀请协助同学认领，并在合并前检查内容；
- 每月和导师做一次简短复盘：哪些页面有帮助、学生在哪一步卡住、下个月改什么；
- 所有涉及个人主页、研究方向、未公开项目或对外承诺的内容，先交导师确认。

负责人试运行 6 周后，根据实际投入和协作情况调整分工。协助同学可以负责单项试读、链接核验、例题改写或页面体验反馈，不需要承担整站维护。

## GitHub 协作流程

1. 从 `main` 创建一个简短分支，例如 `docs/llm-learning-card` 或 `fix/mobile-nav`。
2. 每个 Pull Request 只处理一个清晰目标，并在描述中写明改动、理由和检查方式。
3. 预览修改后的页面；检查手机布局、链接、中文文字和浏览器控制台中的错误。
4. Pull Request 由导师或指定维护者审核。涉及主页导航、公开研究方向、申请说明、个人信息或对外合作的内容，需要导师确认。
5. 审核通过后合并到 `main`。GitHub Pages 会从仓库发布更新；合并后打开线上页面确认实际展示。

建议仓库对 `main` 启用 Pull Request 审核，日常维护不直接推送 `main`。如尚未获得仓库协作者权限，也可以从公开仓库 Fork 后提交 Pull Request。

## 可以提交的内容

- 面向本科生的概念卡、入门练习、术语解释和 FAQ；
- 经核实的公开论文、课程、开源项目和官方文档链接；
- 页面可访问性、移动端排版、文字表达和导航改进；
- 公开 Demo、代码模板及其运行说明；
- 经过确认的学生作品、项目结果和复盘。

新增学习内容请遵循“先精简、再按需扩展”：写清楚学习目标、预计时间、一个可完成的小练习和一个自测问题。优先介绍必要概念，不复制整套课程或整本手册。

## 不要放到公开仓库

- 学生个人资料、联系方式、申请材料、会议记录和内部进度；
- 研究生个人阅读手册、未公开研究 Idea、未发表结果或内部项目文件；
- API Key、访问令牌、密码、私有数据或未经授权复制的材料；
- 未经本人和导师确认的姓名、照片、作品或对外承诺。

公开页面只展示已批准公开的通用方向、学习材料和成果。拿不准时，先把修改留在 Pull Request 中并请导师审核，不要直接发布。

## Pull Request 提交前

- [ ] 这项修改面向谁、帮助他们做什么，描述清楚了吗？
- [ ] 新增材料经过筛选，链接和使用许可已核对了吗？
- [ ] 页面在桌面和手机宽度下都能阅读吗？
- [ ] 没有包含个人信息、内部 Idea、密钥或私有数据吗？
- [ ] 在线页面发布后，是否安排了实际查看？
