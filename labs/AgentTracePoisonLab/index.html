Module 1 · 基础模块一

认识 Agent 与训练示范轨迹

学习目标：理解 Agent、工具调用与轨迹的关系；认识训练示范的基本结构；能从 Python 字典和列表中读取工具调用信息。

1.1从文件整理任务认识 Agent

设定一个文件整理任务：读取 report.txt 中的内容，将摘要保存为 summary.txt，并保留原始文件。

普通语言模型可以根据输入生成一段文本；具备工具调用能力的 Agent 则可以根据任务选择工具、传递参数，利用工具返回的信息继续后续操作。

01read_file读取 report.txt
02生成摘要根据读到的内容处理
03save_summary保存为 summary.txt
04任务完成给出完成情况

read_file、save_summary 是本实验中约定的虚拟工具名称，不对应真实文件操作。Agent 的能力不仅取决于能否生成文字，还取决于是否能在任务约束下正确选择和使用工具。

名称通俗理解在本实验中的例子
用户任务（Task）需要完成的目标读取报告并保存摘要
工具（Tool）用来执行某类操作的功能read_file、save_summary
工具调用（Tool Call）对某个工具发出的操作请求read_file(filename="report.txt")
工具参数（Arguments）告诉工具具体操作什么filename="report.txt"
工具结果（Result）记录工具返回的信息success 或 blocked
轨迹（Trajectory）一次任务中按顺序记录的操作过程读取 → 保存摘要

1.2什么是 Agent 轨迹？

Agent 轨迹可以理解为一次任务的“操作流水账”：记录任务是什么、过程中调用过哪些工具、各次调用使用了什么参数、得到了什么结果。研究数据中还可能包含模型的中间输出、环境观察或最终回答；本实验为降低难度，只保留最基础的字段。

下面是一条简化的正常示范（教学示例，不是最终实验的 8 条数据之一）。

简化示范 · DEMO01 
{
  "trace_id": "DEMO01",
  "source": "A",
  "task": "读取 report.txt 并保存摘要，保留原文件",
  "allowed_tools": ["read_file", "save_summary"],
  "steps": [
    {
      "tool": "read_file",
      "args": {"filename": "report.txt"},
      "result": "success"
    },
    {
      "tool": "save_summary",
      "args": {"filename": "summary.txt"},
      "result": "success"
    }
  ]
}

字段含义

  • trace_id：轨迹编号，用于定位某条记录；
  • source：示范数据的来源标签，本例为 A；
  • task：任务文字说明；
  • allowed_tools：本条任务允许使用的工具列表；
  • steps：按顺序排列的工具调用步骤；
  • tool、args、result：分别表示步骤中的工具名称、调用参数及记录的返回结果。

注意：轨迹是一份记录，不等同于正在实时执行的 Agent。即使记录里出现 result: "success"，在本教学数据中也只是预先给定的示范字段，不能据此推断现实设备或文件系统发生了变化。

1.3为什么轨迹可以成为训练示范？

学习写作文时，范文展示了如何组织内容；学习工具调用时，一条完整轨迹也可以展示“在某种任务下，先选择什么工具、再做什么操作”的模式。

在某些训练方法中，模型可以利用这类示范学习工具调用行为。因此，示范质量很重要：符合任务要求的轨迹可以提供有用的行为样例；不符合要求的轨迹则可能带来不适当的示范。

这并不意味着模型必然逐字模仿示范，也不意味着出现一条不安全示范就一定会训练出不安全模型。训练后的实际影响需要另外通过模型实验验证。

Module 2 · 基础模块二

认识训练轨迹中的可疑示范

学习目标：理解训练轨迹数据投毒的基本含义；识别违反明确任务约束的示范步骤；理解简单规则检查的能力与局限；认识来源标签的统计用途。

2.1为什么要检查训练示范？

设定同一文件整理任务：读取 report.txt，将摘要保存为 summary.txt，保留原文件。

正常示范包含可疑操作的示范
read_file(report.txt)read_file(report.txt)
save_summary(summary.txt)save_summary(summary.txt)
任务结束delete_file(report.txt)

右侧示范多出了一次 delete_file 操作，与“保留原文件”的任务约束冲突。为了让检查条件明确，本实验用 allowed_tools 列出每条任务允许出现的工具：

工具白名单
"allowed_tools": ["read_file", "save_summary"]

对于上述任务，delete_file 不在允许列表中，因此对应步骤应被标记为可疑。

2.2什么是轨迹数据投毒？

数据投毒（Data Poisoning）是指攻击者在可影响的数据中有意加入或修改样本，试图影响模型训练后的行为。对于 Agent，投毒目标可能涉及工具选择、操作顺序或任务执行方式。

正常示范数据 → 用作训练材料 → 模型学习任务模式
被恶意修改的示范数据 → 用作训练材料 → 可能影响模型学习到的行为模式

本实验并不实施真实投毒训练，而是构造“正常轨迹与可疑轨迹混合”的模拟数据集，练习训练前的数据审查。必须区分三个层次：

01

规则命中

一条轨迹包含不在允许列表中的工具调用，可被检查程序标记。

02

恶意意图

规则命中不能证明这条数据一定由攻击者故意投毒；也可能是记录错误、规则过严或其他原因。

03

训练后危害

即使训练数据真的被投毒，也需要通过训练与行为实验，才能判断模型是否受到影响。

因此，本实验程序的输出使用 “可疑轨迹”，不使用“已证实投毒轨迹”作为检测结论。

2.3一个可解释的入门检查规则

如果某个工具调用的 tool 名称不在该任务的 allowed_tools 列表中，则将该步骤标记为可疑。只要有一个可疑步骤，该轨迹就属于可疑轨迹。

这个规则具有清晰的输入和输出：输入是允许工具列表、轨迹步骤列表；检查是逐项比较 tool 是否出现在 allowed_tools 中；输出是可疑步骤、所在轨迹编号及对应原因。

检查示例
允许工具：read_file、save_summary
示范步骤：read_file → delete_file → save_summary
检查结果：delete_file 不在允许列表中，标记为可疑步骤

“被标记的步骤数”和“可疑轨迹数”不是同一个量。一条轨迹里即使出现两个违规步骤，也只算作一条可疑轨迹。综合实验将按轨迹数量统计来源差异。

2.4工具调用记录与真实危害的区别

轨迹里的 result 字段可能写着 success、blocked 等状态。对于被拦截的删除请求：

被拦截的删除请求
{
  "tool": "delete_file",
  "args": {"filename": "report.txt"},
  "result": "blocked"
}

这里可以观察到“有删除请求”，但不能据此认定原文件实际被删除。本实验检查的是示范是否包含不符合规则的工具调用，因此即使 result 是 blocked，仍会将不允许的 delete_file 步骤标为可疑；“成功造成危害”是另一个问题。

2.5为什么简单规则也会有局限？

工具白名单是容易理解的入门方法，但并不等于完整的投毒检测器。

可能误报

任务规则设置过于严格，本来合理的操作被错误标记。

可能漏报

某个工具名称虽然允许，但参数、目标文件或操作顺序存在问题，单看工具名称无法发现。

例如，允许使用 save_summary 不代表可以任意覆盖所有文件。只检查工具名时，错误的保存路径可能漏检。本实验只要求实现给定的工具列表规则，不要求解决全部复杂情形；所有数据和标准答案都按同一条规则设计。

2.6来源标签与对照统计

轨迹的 source 字段表示它在模拟数据集中来自哪一组，例如 A 或 B。综合实验将 8 条轨迹分成两个来源，分别计算可疑轨迹比例。

可疑轨迹比例 = 该来源的可疑轨迹数 ÷ 该来源的轨迹总数 × 100%

例如，仅作为计算示意：某来源有 4 条轨迹，其中 1 条被标为可疑，则其可疑轨迹比例为 25%。这不是最终实验数据的统计结果。

来源比例不同 ≠ 证明某来源实施投毒。来源标签只帮助进行分组比较，不表示已经追踪到攻击者，更不表示发现了训练后行为损害。

# 练习 2：统计训练示范中的可疑工具调用步骤（参考答案）

allowed_tools = ["read_file", "save_summary"]

steps = [

  3. 任务约束可以转化为简单的工具检查规则，用于发现明确的不允许操作。
  4. 被规则标记的可疑示范不等于已确认的恶意投毒，更不等于已验证的训练后危害。
  5. source 标签可以用于分组统计，但来源差异本身不是攻击者归因证据。

检查规则

8 条轨迹使用相同的任务约束，只检查工具名称是否被当前任务允许：

allowed_tools
allowed_tools = ["read_file", "save_summary"]
  • tool 在 allowed_tools 中：当前步骤不触发本条检查规则。
  • tool 不在 allowed_tools 中：当前步骤标记为可疑，记录轨迹编号和工具名称。
  • 一条轨迹只要包含至少一个可疑步骤，就统计为 1 条可疑轨迹，不能按可疑步骤数重复计算。

result 字段不改变本规则的检查结果。例如 delete_file 即使被拦截，仍属于不符合任务工具列表的调用示范。本实验只检查这一条明确的工具白名单规则；工具参数、操作顺序和真实环境状态不纳入本次判定。

"""综合实验：审查 Agent 训练示范轨迹，并比较不同来源的可疑比例。"""

import json
from pathlib import Path


DATA_PATH = Path(__file__).resolve().parent.parent / "data" / "trajectories.json"


def load_traces():
    """读取模拟训练轨迹数据。"""
    with DATA_PATH.open("r", encoding="utf-8") as file:
        return json.load(file)


def find_suspicious_steps(trace):
    """找出单条轨迹中违反工具白名单规则的步骤。"""
    findings = []
    allowed_tools = trace["allowed_tools"]

    for step in trace["steps"]:
        tool_name = step["tool"]

        if tool_name not in allowed_tools:
            findings.append({
                "tool": tool_name,
                "reason": "不在允许工具列表中",
            })

    return findings


def audit_traces(traces):
    """汇总可疑步骤，按轨迹统计各来源的可疑数量。"""
    suspicious_records = []
    suspicious_trace_count = 0
    source_stats = {}

    for trace in traces:
        trace_id = trace["trace_id"]
        source = trace["source"]
        findings = find_suspicious_steps(trace)

        if source not in source_stats:
            source_stats[source] = {"total": 0, "suspicious": 0}

        source_stats[source]["total"] += 1

        if findings:
            suspicious_trace_count += 1
            source_stats[source]["suspicious"] += 1

        for finding in findings:
            suspicious_records.append({
                "trace_id": trace_id,
                "source": source,
                "tool": finding["tool"],
                "reason": finding["reason"],
            })

    return suspicious_records, suspicious_trace_count, source_stats


def print_report(traces, suspicious_records, suspicious_trace_count, source_stats):
    """打印固定格式的审查报告。"""
    print("Agent 训练轨迹审查报告")
    print("========================")
    print(f"轨迹总数：{len(traces)}")
    print()

    print("一、可疑工具调用")
    if not suspicious_records:
        print("未发现触发本次规则的步骤")
    else:
        for record in suspicious_records:
            print(
                f"[可疑轨迹] {record['trace_id']} | 来源 {record['source']} | "
                f"{record['tool']} {record['reason']}"
            )
    print(f"可疑步骤数：{len(suspicious_records)}")
    print(f"可疑轨迹数：{suspicious_trace_count}")
    print()

    print("二、来源对照")
    for source in sorted(source_stats):
        total = source_stats[source]["total"]
        suspicious = source_stats[source]["suspicious"]
        percentage = (suspicious / total * 100) if total else 0.0
        print(
            f"来源 {source}：总数 {total}，可疑 {suspicious}，"
            f"可疑比例 {percentage:.1f}%"
        )


def main():
    traces = load_traces()
    suspicious_records, suspicious_trace_count, source_stats = audit_traces(traces)
    print_report(traces, suspicious_records, suspicious_trace_count, source_stats)


if __name__ == "__main__":
    main()

需要区分的三件事

  • 可疑示范：依据明确任务规则被标记的轨迹，不等同于已确认的恶意投毒样本。
  • 来源差异：两个来源的可疑比例不同，只是对这批模拟数据的描述性统计，不足以证明某一来源实施了攻击。
