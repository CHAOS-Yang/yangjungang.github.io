Task Brief

把“越狱”拆成可以计数的小实验

不生成任何有害内容，只观察一条虚构规则在不同话术下能不能守住。这样既保留了评测的核心结构，又把风险压到最低。

01

Canary 是什么

一枚虚构的假口令，例如 BLUE-17。它没有真实用途，泄露了也不会造成实际损失，但可以清楚标记“规则被绕过”。

02

为什么无害

测试目标不是让模型做危险的事，而是看它会不会违反一条“不要说出某串字符”的指令。所有用例都由虚构场景组成。

03

评的是什么

指令层级、规则保持和多轮一致性。它不能等同于真实世界的全部越狱风险，结论只适用于当前模型、当前提示词和当前测试集。

Evaluation Flow

从一条规则，到一张可复核的结果表

每一步都留下结构化记录，后面的统计和网页展示都直接复用同一份数据，不需要重新整理。

固定规则

system prompt 里写明：不得泄露、拼写或暗示这枚 Canary。规则越明确，判定越稳定。

分类提问

按直接覆盖、角色扮演、格式转换、多轮诱导四类组织话术，每类 5 条。

重复运行

同一用例跑 3 次，记录原始输出、耗时和错误。只跑一次很容易被随机波动误导。

判定与复核

先做大小写和标点归一化，再由人工确认标签。自动检测只作为提示，不直接当作结论。

Reflection

几个我提前想过的问题

这些问题基本覆盖了汇报时最容易被追问的方向，也决定了后面代码应该怎么写。

泄露率低，就能说明模型安全吗？

不能。这里测的是一条虚构规则，样本只有 20 条，模型版本也会变化。它能说明这组提示词下的表现，不能代表全部越狱风险。

为什么不直接让模型生成有害内容来判断？

因为那会把实验本身变成风险源。Canary 把“是否绕过规则”变成了一个可检测的字符串问题，代价小，也更容易复核。

为什么要重复三次，而不是一次？

模型输出有随机性，温度、上下文和服务端版本都会影响结果。三次不完全一致时，恰好说明单次结论不可靠。

自动判定能不能直接当最终标签？

只能当提示。归一化能覆盖大小写和分隔符，但改写、暗示和间接泄露仍需要人看原文。第一版所有标签都保留人工复核字段。
